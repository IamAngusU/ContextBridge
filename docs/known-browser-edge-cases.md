# Known browser edge cases

ContextBridge drives third-party web chats through their visible UI. While dogfooding it, we hit these provider states. A visible answer is not automatically a finished, usable result.

## Reproduced and handled

- **Gemini's busy flag can outlive the answer.** We saw new text while the last response still had `aria-busy="true"`. The Stop control had already gone. v0.5.13 accepts that turn only after the new text stays unchanged for 12 seconds, the composer is ready, and no other busy signal remains. The live DOM heartbeat reports indicator types, not chat text.
- **Gemini can silently switch modes under peak demand.** A captured Pro turn displayed “Pro ist derzeit sehr gefragt” and explicitly said another model was used without charging the limit; the picker later showed Flash Erweitert. This is provider-side fallback, **not** proof of a rate limit. v0.5.14 rejects a Pro job when its new turn contains that fallback notice, even if the picker label has not yet changed. Earlier mode-family checks also compare the visible selection; the terminal separates *requested* from *tab-reported*. A UI label cannot prove the provider's undisclosed backend model version.
- **Gemini's composer is replaced and Send disappears.** Switching modes or tools can remount the Quill editor; after submission, an empty editor may have no Send button at all. We rebind the editor, verify the exact retained draft, and finish on a stable new response instead of waiting for Send forever. A selected Music tool is cleared before a plain-text job; that is not a claim that music generation works.
- **An image can arrive after the job has timed out.** In one live Gemini run, the last turn contained a loaded generated `blob:` image, but the bridge had already returned `browser_timeout`. A resume-only retrieval recovered the actual PNG without sending the prompt again. v0.5.14 also treats the requested number of fully loaded images as completion evidence when only Gemini's stale `aria-busy` remains; the bytes still have to pass artifact validation.
- **A ChatGPT retry banner is not a rate limit.** We captured “Etwas ist schiefgelaufen. Bitte versuche es erneut” on the new user turn with a Retry control and no visible limit notice. Earlier answer text could previously contaminate the fallback classifier. v0.5.14 scopes this error to the new turn and reports `browser_provider_error` without the rate-limit cooldown.
- **A stale browser-job error is not a failed connection.** After clicking Connect in Opera, the popup still showed an older “tab did not finish reloading” error while the bridge was stopped. v0.5.15 separates connection errors from per-tab job failures and verifies the first authenticated heartbeat before reporting Connected. Recovery now probes for the actual AI prompt instead of relying on Opera's tab-loaded flag alone.
- **An old Gemini answer can briefly reappear during the next job.** In a parallel three-tab smoke test, the terminal streamed a previous Music player's text while the new job was generating, then the correct final answer. The player's changing timer had made its old response differ from the baseline. v0.5.17 gates provisional text on a genuinely new assistant turn (response count or stable element identity) as well as a live Stop/streaming control. If the page cannot establish a new turn, final output still works but provisional text is withheld.
- **Clearing a saved Gemini draft exposed a page-wide Select All.** In the first live draft-preservation test, the unsent text was saved locally, but the following prompt was not retained and the job correctly failed before Send. The Quill insertion path still used the browser's global `selectAll`, which could mark the whole page after clearing the editor. v0.5.18 selects only the editor's contents before inserting; a serialized-injection regression test checks that no global Select All command runs. The live E2EE retest sent the exact marker and returned it in 29.7 seconds; the editor was empty and the draft history still had exactly one record for that Gemini tab.
- **ChatGPT can leave Stop visible after the answer text appears complete.** A live draft test returned the exact requested marker, but the page still exposed `stop-button` and `streaming-animation` for minutes. v0.5.18 never treats that text alone as success: for a plain text turn unchanged for 90 seconds, it reloads the same tab once and verifies the finished turn without resending the prompt. This one-shot recovery is covered by an isolated-injection test, but was not live-triggered after the fix. A manual reload removed Stop; the next same-session E2EE text test returned `BRIDGEOK` in 9.8 seconds. A still-busy page remains a failed/needs-attention job.
- **Generated ChatGPT images can be file cards, not `<img>` elements.** A live E2EE turn visibly produced `turquoise_bridge.png`, but v0.5.15 found zero transferable images: the new assistant turn exposed an open-file button and a separate download button, with no direct image URL. v0.5.16 opens the new card's preview and requires real image bytes. A second live E2EE run saved and validated a 1024×1024 PNG from a turn whose DOM heartbeat still reported zero inline images.
- **A three-image follow-up may need its prior image reattached.** ChatGPT answered a strict series request by asking for the prior bridge image instead of creating files. The bridge correctly rejected that turn (three required, zero received). Repeating the same-session request with `--attach-image` and `--min-images 3` saved three distinct, valid 1254×1254 PNGs. The provider's request for missing context is not a transfer failure.
- **Gemini Music exposes a video player.** The captured completed turn contained `generated-music` with a `video[src]` on Google's media host and an MP4 filename. v0.5.16 collected it after explicit browser permission: the live E2EE run saved a 5.7 MB MP4, `ffprobe` found AAC audio, and a full `ffmpeg` decode measured non-silent audio (-14.3 dB mean, -0.1 dB peak). Text saying music was created cannot satisfy `min_media`. Gemini did not honor the requested approximate ten-second duration; the actual file was about 102 seconds.
- **Gemini's Music option can render after the fixed click delay.** A live job failed safely with `browser_music_tool_unavailable` before Send, even though a screenshot and DOM dump showed an enabled `Musik erstellen` checkbox in Gemini's animated CDK menu. v0.5.19 waits for the option, avoids closing an already-open menu, and checks the selected-tool chip before sending. The E2EE retest from the already-open menu transferred a 3.6 MB MP4 with a 61-second, decodable, non-silent AAC stream. A failed lookup still never counts as music output.
- **Gemini's model labels contain invisible non-breaking spaces.** The live picker advertised `3.6 Flash`; typing the visually identical `3.6 Flash` with normal spaces was rejected before Send. The exact copied label succeeded. v0.5.19 folds Unicode whitespace only for browser model matching and browser allowlists, keeping local model IDs strict.

## Reported; reproduction still needed

- **ChatGPT image generation can sit at 99%.** A page reload once exposed a finished conversation, but not necessarily a delivered image. The bridge tracks the progress bar, attempts one bounded recovery when generation stalls, and requires actual transferred image bytes for an image job. Multi-image series must meet the requested count; a text claim or a loading placeholder is not an image.
- **ChatGPT can pause for a safety check or parallel-work pressure.** Neither screen should become answer text. A short capacity pause is not automatically an account rate limit; we still need redacted DOM fixtures to distinguish them reliably.
- **Gemini video generation is intentionally untested.** The Music MP4 above is an audio deliverable with visuals, not a video-generation test. We have not spent money/credits on Gemini's separate video workflow and do not claim that its submission, completion, file transfer, or E2EE path works yet.

## Diagnostic idea, not a default permission

For the stuck-Stop case, compare one consented test chat's DevTools Network completion events with its DOM transitions. Only adopt a narrowly scoped signal if it is more reliable than the visible UI. Do not continuously capture request bodies, cookies, authorization headers, or unrelated chats just to guess whether one answer finished.

For a new case, capture provider, locale, visible model, approximate time, whether Send/Stop was available, and a *redacted* status-element transition (`role`, `aria-label`, `data-testid`, `aria-busy`). Do not post full chat HTML, account details, tokens, or private prompts. Ambiguous UI stays a failed/needs-attention job, never successful model output.
