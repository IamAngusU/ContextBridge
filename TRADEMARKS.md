# ContextBridge project identity

The ContextBridge name, wordmark, logo, and related visual identity identify
the project maintained by Angus Uelsmann. The software license covers the code
and documentation; it does not grant a separate right to use those identifiers
in a way that suggests sponsorship, certification, endorsement, or official
status.

You may, without separate permission:

- truthfully state that software is compatible with, built with, or based on
  ContextBridge;
- link to the official repository and reproduce the name when describing the
  origin of unmodified software;
- redistribute an unmodified official release while preserving its notices;
  and
- use the name in commentary, education, reviews, issue reports, and other
  nominative references.

If you distribute a materially modified fork as its own product or service,
use a distinct primary name and visual identity. You may describe it as “based
on ContextBridge,” but should state clearly that it is independently maintained
and is not an official ContextBridge release.

Do not use the ContextBridge identifiers to imply an endorsement or official
relationship that does not exist, or register a confusingly similar product,
package, service, account, or domain name.

`ContextBridge Verified` and any corresponding badge identify a signed,
unexpired statement issued under a project verification program. They may be
used only for the exact product, artifact, scope, and validity window named in
that statement and only after such a program and its terms have been publicly
announced. Running the free conformance suite or verifying a signature from an
arbitrary third-party key does not grant that designation.

This policy is intended to preserve accurate attribution and prevent user
confusion, not to prevent honest discussion, interoperability, or compatible
independent implementations. Questions or permission requests may be opened as
a licensing discussion in the official repository.
